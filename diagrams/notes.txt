TASK
  knows (attributes): description, type (walk/feeding/medication/appointment),
    date and start time, duration, priority, is_done, recurrence (none/daily/weekly)
  does (methods): mark_complete(); if it repeats, the next occurrence gets created

PET
  knows: name, species, age, list of its tasks
  does: add_task(task), remove_task(task), get_tasks()

OWNER
  knows: name, list of pets, available time per day
  does: add_pet(pet), get_all_tasks() (collects tasks across all pets)

SCHEDULER
  knows: which Owner it is scheduling for (and through the owner, their pets and tasks)
  does:
    - get_todays_schedule(): today's tasks sorted by time, then priority
    - detect_conflicts(): finds tasks whose time ranges overlap
    - get_pending_tasks(): tasks that are not done yet
    - handle_recurring(task): when a repeating task is completed, creates the next one

WHERE TASKS LIVE:
  Tasks live on the Pet, because "walk Max at 8" belongs to Max. The Owner can
  collect them across pets, and the Scheduler reads them through the Owner,
  so the Scheduler does not duplicate any data.
